# Penny release status — 12 November 2026

Penny has a signed Android App Bundle, a saved Play Store listing and an internal testing draft. It is **not ready for a public rollout**: live authentication, billing, reviewer access, required Play declarations and the closed-test gate still need completion.

- 62 unit/database tests and 22 browser flows pass. The browser suite covered first-run setup, expenses and income, wallets, budgets, imports and exports, notifications UI, large numbers at 320 px, and the Premium sign-in gate. The production web build and Android sync pass.
- The latest bundle is at android/app/build/outputs/bundle/release/app-release.aab (built 12 November 2026). The signature checker reports “jar verified.” Google Play accepted it as version 1 (1.0), target SDK 36, in an **internal testing draft** named “Penny 1.0 internal test.” The upload key and signing settings are ignored by Git; back them up securely before publishing any release.

Google Play accepted the AI asset labels and saved the listing in Publishing overview, ready to send for review. The app-level trader status and Penny Terms of Service URL are saved there too. No release has been published or sent for review.
- Four penny_ database migrations and four penny- Edge Functions are live in Supabase project vcfalijtdakuyyfbdghy, shared with another app. Penny tables use row-level security. Penny deletion removes Penny data while leaving the shared sign-in identity and other-app data intact.
- Published [privacy](https://sites.google.com/view/penny-rzstudios/privacy-policy), [terms](https://sites.google.com/view/penny-rzstudios/terms-conditions), and [deletion](https://sites.google.com/view/penny-rzstudios/account-deletion) pages are linked in Penny and Play Console where applicable. The public site homepage says “Coming soon to Google Play.”
- Supabase accepts an email OTP request. Inbox delivery, code verification, Android callback and Google sign-in have not been proven end to end. Penny's native sign-in passes app.penny.expenses://auth/callback explicitly; the Supabase redirect allow-list includes it. The shared project's fallback Site URL is still localhost, so a live native sign-in test is required.

## Remaining release gates

1. **Reviewer access:** The dedicated Supabase reviewer login noreply.rzstudios@gmail.com exists, with a password known only to the publisher. The publisher explicitly approved a reviewer-only lifetime Premium grant; the `penny_entitlements` row was verified with `lifetime = true` on 12 November 2026. The Play Sign in details form is prepared with accurate instructions, but the publisher must enter its password directly, confirm full access and save the declaration. The installed-app sign-in still needs a live test.
2. **Email and Google sign-in:** Rotate the Gmail app password shared during development, then enter the replacement directly in Supabase custom SMTP. Use neutral RZ Studios OTP templates because Auth email templates are shared by every app in this Supabase project. The RZ Studios Google Cloud account passed its first welcome prompt, but a fresh terms prompt appeared on the New Project page; the publisher must accept it there. Then configure a Google OAuth client and provider. Test new email signup, returning-user OTP, Google sign-in, and both Android cold-start callbacks on the Play-installed build. Do not place client secrets in Git or public frontend configuration.
3. **Billing:** Play Console blocks Subscriptions until a Google Payments merchant profile is created. The publisher must complete that financial account setup with legal business and payout details; Bangladesh is eligible for merchant registration. Then create subscription `penny_premium` with a paid monthly US$5 target base plan and no trial, and configure an Android Publisher API service account with minimal rights. Store its JSON only as an Edge Function secret. Test purchase, renewal state, cancellation, expiry, refund, restore and account switching through a Play test track. The browser UI cannot prove live Play Billing.
4. **Console declarations:** Play Dashboard shows 8 of 12 app-information tasks complete. Finish Sign in details, content rating, target audience and Data safety. Target audience is blocked by incomplete Sign in details. Starting the content-rating questionnaire accepts IARC terms and requires the publisher's own decision. Check every declaration against the final build and published policy.
5. **Device validation:** Add authorized internal testers, publish the internal draft after sign-in and Premium access are ready, then install it from Play. Check Android notifications, offline persistence, import/export with real files, sync opt-in and two-device conflicts, deletion, font scaling and screen-reader access. Back up the upload key before publishing the first release.
6. **Testing gate:** This Play Console explicitly requires a closed release with at least 12 opted-in testers for at least 14 days before applying for production. It currently shows 0 opted-in testers. Public deployment cannot occur before that period completes.
7. **Worldwide availability:** Review local privacy, consumer, subscription, tax and cross-border obligations for each offered region. The app, generated legal text and automated checks do not establish worldwide legal compliance. Limit launch countries if a requirement cannot be met.

Rotate the database and Gmail credentials exposed during development before launch. Keep the new values, upload key and service-account JSON out of this public repository and chat.
